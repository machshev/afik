# BK4819 command boundary

`radio-bk4819` is a hardware-independent, post-initialization command driver.
It is `no_std`, heap-free, bounded, and uses integer units. Its source and
confidence contract is `docs/hardware-evidence.md`; this document describes the
software boundary built from that evidence.

## Logical bus and frequency

The adapter contract exposes fallible complete reads and writes using validated
7-bit register addresses and 16-bit values. It does not define GPIO pins,
3-wire edge timing, electrical direction switching, or a concrete peripheral.
An adapter error means the operation did not complete.

Frequencies must be exactly divisible by 10 Hz. The resulting 32-bit word is
written low half to `REG_38` and high half to `REG_39`. The driver deliberately
does not encode the conflicting published BK4819 band ranges as validation;
channel policy and later evidenced board limits are separate concerns.

## State and command order

A newly wrapped bus is `Unknown`. A successful `REG_30 = 0x0000` establishes
`Standby` and is the only recovery from unknown or faulted state. Receive and
transmit command plans are ordered as:

1. write neutral mode `REG_30 = 0x0000`;
2. write the frequency low word to `REG_38`;
3. write the frequency high word to `REG_39`;
4. write the selected inferred mode to `REG_30` last.

The bounded receive mode is `0xBEF1`; the bounded transmit mode is `0x80FE`.
These combined values and their ordering are low-confidence AFIK design
inferences, not copied vendor initialization sequences. Receive status decodes
only the recorded read-only RSSI and squelch fields, preserving RSSI in signed
half-dBm integer units.

Every bus error immediately latches `Faulted`. Invalid state and unrepresentable
frequency return before a command plan starts. A partial plan never updates the
driver to its intended final state.

## TX authority

`radio-tx-policy` remains the sole safe constructor of `TxAuthorisation`, and
each token records its approved `TxClass`. The BK4819 driver's only path to
`0x80FE` requires a borrowed token, compares its class with the requested active
channel before any bus operation, and records that class in the established TX
state. A mismatch, invalid state, or prior fault denies the final TX-mode write.

Stopping a known TX session writes neutral mode. This boundary proves only that
modeled TX commands cannot bypass central software policy. It does not prove
that the register composition is correct for physical silicon or that external
RF paths are disabled.

## Deliberate exclusions

There is no reset/initialization table, physical bus, MCU pin mapping, crystal
or calibration choice, interrupt path, board RF switch, filter, audio route,
power level, external PA control, flashing support, physical receive claim, or
on-air test. Those remain blocked by `RISK-002`, `RISK-005`, and `RISK-007`.

## Receive configuration and metering

Work Package 27 adds a complete receive path built from `EVID-BK4819-053`,
where the pinned K1 reference firmware is the authoritative source for register
values that primary Beken documentation does not define. See `ADR-051`.

`configure_receive` accepts one `ReceiveSetup` (frequency, modulation,
bandwidth, receive tone, calibration-supplied squelch thresholds, and initial
audio routing) and writes, in order:

1. neutral mode, power blocks `REG_37 = 0x1F0F`, neutral mode, receive mode;
2. the demodulator block for FM, AM, or USB, plus audio, AF DAC gain, tail, and
   the AFC enable which only FM leaves on;
3. filter bandwidth `REG_43`;
4. the AGC gain tables and threshold;
5. the frequency low and high words;
6. squelch glitch, noise, and RSSI thresholds;
7. sub-audio control: disabled, CTCSS with its `REG_07` control word, or CDCSS
   with its baud word and both halves of the 23-bit Golay code word;
8. the interrupt mask and a cleared latch;
9. the VHF or UHF low-noise-amplifier path;
10. the audio output route.

The receive path can only be entered from standby or receive, and any bus error
latches `Faulted` exactly as the existing command plans do. The transmit mode
word is never written by this path.

`receive_metrics` samples RSSI in signed half-dBm units, the raw glitch and
excess-noise indicators, the carrier squelch link, and the latched tone status
for the channel's tone kind. `should_unmute` requires an open carrier squelch
and, on a tone-coded channel, a currently matched tone; an indeterminate tone
result never unmutes.

Squelch thresholds are per-unit calibration data. `SquelchThresholds` validates
that RSSI opens above its close threshold and that noise and glitch open below
theirs, but the driver never invents a value. `RISK-028` tracks the missing
calibration source.

## Board bus

`radio-firmware-k1::bk4819_bus` sequences the register bus over the pinned K1
pinout recorded in `EVID-K1-054`: chip select `PF9`, clock `PB8`, and the shared
bidirectional data line `PB9`, bit-banged most significant bit first with one
microsecond between edges and bit 7 of the address requesting a read. A board
adapter supplies the pin and delay primitives, so the complete transfer order is
host tested. No AFIK transfer has been performed on hardware; see `RISK-027`.
